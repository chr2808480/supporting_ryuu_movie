# 星軍基地を本番で動かす手順

`hiroba.html`（星軍基地）を、本物の投稿ができる状態にするための手順です。
接続先は `assets/js/hiroba-config.js` に入っています。

**用意するもの**：パソコンのブラウザ（Chrome など）、Google アカウント、クレジットカード
**自分のパソコンに入れるものはありません。** 作業はすべてブラウザの中で行います。

## 先に、ことばの説明

| ことば | 意味 |
| --- | --- |
| Firebase コンソール | Firebase の設定をする管理画面。<https://console.firebase.google.com/> |
| Cloud Shell（クラウドシェル） | Firebase コンソールの中で開ける、文字を打って命令する黒い画面。Google のコンピューターで動くので、自分のパソコンには何も入らない。無料（週50時間まで） |
| デプロイ | サーバー側のしくみ（投稿の受付・チェックなど）を Firebase に送って、動かし始めること |
| 合言葉（HIROBA_SECRET） | 投稿者の IP アドレスを暗号化するための秘密の文字列。手順7で自動で作られる |

## 全体の流れ

| | やること | どこで | 時間の目安 |
| --- | --- | --- | --- |
| 手順1〜5 | 準備（クリック操作） | Firebase コンソール | 20分 |
| 手順6〜7 | 1行を貼り付けて、質問に答える | Cloud Shell | 15分 |
| 手順8 | 「デプロイできた」と伝える | Claude | — |
| 手順9 | 運営者として有効にする | kanri.html | 3分 |
| 手順10 | 試してから公開 | ブラウザ | 15分 |

## 手順1〜5：Firebase コンソールでの準備

1. **プロジェクトを作る**（済み：`spporting-ryuu-movie`）
   Google アナリティクスは使いません。作るときにオンにした場合は、「プロジェクトの設定」→「統合」から Google アナリティクスとの連携を外してください。
2. **Blaze プランにして、予算アラートを設定する**
   左下の「Spark」（プラン名）→「プランをアップグレード」→ Blaze を選び、クレジットカードを登録します。
   続けて予算アラート（例：500円）を設定します。迷ったら公式の [Avoid surprise bills](https://firebase.google.com/docs/projects/billing/avoid-surprise-bills) を見てください。
3. **Firestore を作る**
   左のメニュー「Firestore Database」→「データベースの作成」。
   エディションは **Standard**、ロケーションは **`asia-northeast1`（Tokyo）**、モードは **本番環境モード** を選びます。
   ※ ロケーションは後から変えられません。
4. **ログインの方法を有効にする**
   左のメニュー「Authentication」→「始める」→「ログイン方法」タブ →「メール / パスワード」を開き、
   **「メール / パスワード」と「メールリンク（パスワードなしでログイン）」の両方をオン** にして保存します。
   続けて「設定」タブ →「承認済みドメイン」→「ドメインの追加」で **`chr2808480.github.io`** を追加します。
5. **ウェブアプリの接続設定を Claude に渡す**（済み）

> 画面の名前は変わることがあります。見つからないときは、Claude に画面の様子を伝えてください。

## 手順6：Cloud Shell を開く

1. Firebase コンソールで、プロジェクト `spporting-ryuu-movie` を開きます。
2. 画面の右側にあるメニューから **「Cloud Shell」** をクリックします。
3. 画面の下に、黒い画面（Cloud Shell）が出てきます。「承認」を求められたら「承認」を押します。

この黒い画面に、手順7の1行を貼り付けて使います。

## 手順7：1行を貼り付けて、Enter を押す

次の1行を **まるごとコピー** して、黒い画面をクリックしてから貼り付け、**Enter** を押します。

```bash
git clone https://github.com/chr2808480/supporting_ryuu_movie.git && cd supporting_ryuu_movie/firebase && bash setup.sh
```

- 貼り付けは **Ctrl+V**（Mac は **⌘+V**）。うまくいかないときは、右クリック →「貼り付け」。
- この1行は、①このサイトのファイル一式を GitHub から Cloud Shell にコピーし、②その中の `firebase` フォルダに移り、③設定のプログラム（`setup.sh`）を動かします。

### 聞かれることと、答え方

| 画面に出る質問 | 答え方 |
| --- | --- |
| 「済んでいれば y を入力して Enter」 | 手順1〜4が済んでいれば `y` を入力して Enter |
| 「プロジェクトID … [spporting-ryuu-movie]」 | 何も入力せず Enter |
| 「運営者ページにログインするメールアドレス」 | 運営者のメールアドレスを入力して Enter（2人以上ならカンマ区切り） |
| （1〜2分待つ） | 部品の準備です。そのまま待ちます |
| 「次の合言葉を…必ず控えてください」 | 枠の中の文字列をコピーして、**パスワード管理アプリなどに保存**してから Enter |
| （5〜10分待つ） | Firebase に送っています。英語の文字がたくさん流れますが、そのまま待ちます |
| 「★ できました！」 | 完了です。手順8へ |

**合言葉について**：人には見せないでください。開示請求を受けたとき（めったにありません）に、投稿者の IP アドレスを読むのに使います。なくすと読めなくなります。

### 途中で止まったとき

- 「止まりました：」のあとに、何をすればよいかが日本語で出ます。そのとおりにしてから、もう一度実行します。
- もう一度実行するときは、次の1行を貼って Enter（ファイルはもうコピー済みなので、最初の1行とは違います。GitHub の最新の状態に合わせてから実行します）。
  ```bash
  cd ~/supporting_ryuu_movie/firebase && git fetch origin && git reset --hard origin/main && bash setup.sh
  ```
- 最初の長い1行を2回貼ると、フォルダの中に同じフォルダがもう一つできてしまいます。そうなったら、次の1行で作り直します（消えるのは Cloud Shell の中のコピーだけで、GitHub のものは消えません）。
  ```bash
  cd ~ && rm -rf supporting_ryuu_movie && git clone https://github.com/chr2808480/supporting_ryuu_movie.git && cd supporting_ryuu_movie/firebase && bash setup.sh
  ```
- 日本語入力がオンのままでも答えられますが、うまくいかないときはオフ（半角英数）にしてください。
- 何度実行しても大丈夫です。合言葉は作り直しません。
- 英語のエラーだけが出て止まったときは、その文字をコピーして Claude に貼ってください。

## 料金について

- **Blaze プラン（従量課金）が必要です。** メールリンクでのログインは、無料の Spark プランだと1日5通までしか送れないためです。Cloud Functions と自動削除も Blaze でしか使えません。
- Blaze にも無料枠があり、ファンの交流スペースの規模なら、基本は **月0円** の見込みです（Firestore：1日あたり読み取り5万件・書き込み2万件、Cloud Functions：月200万回の呼び出しなど）。部品の保存で数円程度の請求が出ることはあります。
- 毎日4時の自動削除（参加登録のないアカウント）は Cloud Scheduler を1件使います。Cloud Scheduler は請求先アカウントごとに月3件まで無料で、それを超えると1件あたり月0.10ドルです（デプロイのときに自動で有効になります）。
- トップページの来訪者カウンターは、来訪1回（同じタブで開き直したときは数えない）につき、関数の呼び出し1回と Firestore の読み取り1件・書き込み1件を使います。
- **Firestore には使いすぎの上限をかけられません。** 予算アラート（手順2）は必ず設定してください。荒らし対策として、サーバー側は同時に3つまでしか動かないようにし、一度に読める件数も絞っています。

## 日々の運営（kanri.html）

- **確認待ち**：リンクを含む投稿・返信が並びます。「公開する」か「非表示・処置へ」。運営者が書いたものは確認待ちにならず、すぐ公開されます。
- **運営者として基地に書く**：`kanri.html` にログインした同じブラウザで `hiroba.html` を開くと、運営者として投稿・返信できます（初めてのときは表示名を決めて参加登録）。運営者の投稿・返信には「運営」の印が付き、運営者の投稿への返信と運営者の返信は、同じ相手への返信の上限（24時間で3回）に数えません。
- **未対応の通報**：「投稿者への処置へ」で、注意・投稿の非表示・7日間の投稿停止・利用停止を記録します。利用停止にすると、その人のログイン情報と投稿・返信もすべて消えます（元に戻せません）。
  記録したら「通知メールを作る」を押すと、どの投稿がどのルールに当たるか・処置の内容と期間・異議の申立て方を書いたメールが、メールアプリに用意されます（利用規約 第8条）。
  メールアプリによっては長い本文が途中で切れるので、本文が最後の「ryuu星軍 本部 運営」まで入っているか確かめてから送ります。切れていたら、運営者ページに出る宛先・件名・本文をコピーして送ります。
  処置をしなかった通報も、確かめたら「対応済みにする」を押します（押した日から90日で消えます。押さないままでも、通報から180日で消えます）。
- **非表示にした投稿**：異議が通ったら「公開に戻す」。投稿停止の取り消しは、処置の画面の「投稿停止の解除」。
- **基地の状態とお知らせ**：運営者不在（新規投稿をお休み）と、お知らせ欄の文を変えられます。
- **開示請求を受けたとき**：まず専門家に相談してください。IP アドレスを読む必要があるときは、Cloud Shell で次のように実行します（`…` の部分は合言葉と、Firestore の `ipLogs` にある `ip` 欄の値）。
  ```bash
  cd ~/supporting_ryuu_movie/firebase && HIROBA_SECRET='…' node scripts/decrypt-ip.mjs 'v1:…'
  ```

## 詳しい人向け

### しくみ

```
GitHub Pages（hiroba.html・kanri.html）
   │  読む：Cloud Firestore（公開中の投稿・返信など。ルールで守る）
   │  書く：Cloud Functions（すべての書き込みはここで確かめてから保存）
   │  ログイン：Firebase Authentication（メールのリンク。パスワードなし）
   ▼
Firebase（Google LLC）── Firestore・Functions は東京（asia-northeast1）、Authentication は米国
```

| 置き場所 | 中身 |
| --- | --- |
| `setup.sh` | 手順7で動かす設定プログラム（Firestore の場所の確認、運営者メールの保存、部品の準備、合言葉の登録、デプロイ） |
| `functions/index.js` | 投稿・返信・編集・削除・★・通報・退会・運営者の処置と、参加登録のないまま7日たったアカウントの削除（毎日4時）。参加登録の受付開始（`OPEN_AT`。2026-10-23 6:00 より前は運営者のメールアドレスだけ）、受付時間（23時〜6時はお休み）、運営者不在、同じ相手への返信は24時間で3回まで（運営者の投稿への返信と運営者の返信は数えない）、運営者の投稿・返信の「運営」の印（`byAdmin`）、リンクを含む投稿の保留、個人情報らしい文字列の確認、20秒の連投防止、ブロック、投稿停止・利用停止をここで判定する。トップページの来訪者カウンター（`countVisitor`。合計の数だけを `stats/visitors` に持ち、誰が来たかは記録しない）もここ |
| `firestore.rules` | 読み書きの決まり。書き込みは Functions だけ（例外はミュート・ブロックの設定）。★の数は投稿した本人だけ、通報は運営者だけ、IP の記録と来訪者の数は誰も画面から読めない |
| `firestore.indexes.json` | 検索用の索引と自動削除（TTL）。IP の記録は90日、対応済みの通報は90日（未対応のままなら通報から180日）、利用停止の記録は1年で消える |
| `web/entry.js` | ブラウザで使う Firebase の部品。`npm run build:web` で `assets/js/vendor/firebase-hiroba.js` を作る |
| `scripts/decrypt-ip.mjs` | 開示請求のときに、暗号化した IP を読む道具 |
| `test/` | エミュレーター（手元で Firebase を再現するもの）でのテスト |

期間や回数を変えるときは、`functions/index.js` の `RULES` と、`privacy.html`・`terms.html`・`hiroba.html` の記載を一緒に直してください。
参加登録の受付開始を変えるときは、`functions/index.js` の `OPEN_AT`・`assets/js/hiroba.js` の `CONFIG.openAt` を同じ日時にします（11/14 の正式オープンの告知は `assets/js/main.js` の `LAUNCH_AT` で、関数とは関係がない）。テストでは `functions/.env.demo-hiroba` の `HIROBA_OPEN_AT` で過去の日時にしています（本番では使われません）。
運営者のメールアドレスは `functions/.env.（プロジェクトID）` に保存されます（`.gitignore` で公開しないようにしてある）。

### 自分のパソコンで行う場合

Node.js 22 を入れたうえで、`setup.sh` と同じことを手で行います。

```bash
cd firebase
npm install && (cd functions && npm install)
npx firebase login
npx firebase functions:secrets:set HIROBA_SECRET --project spporting-ryuu-movie   # 32文字以上のランダムな値
npx firebase deploy --only firestore,functions --project spporting-ryuu-movie      # ADMIN_EMAILS を聞かれる
```

### テスト

```bash
cd firebase
npm test            # ルールと関数（エミュレーター。Java 21 以上が必要）
npm run test:e2e    # 画面を通した確認（npx playwright install chromium が必要。日本時間の6時〜23時に実行）
```

Firebase の部品（`firebase` パッケージ）を更新したら、`npm run build:web` で `assets/js/vendor/firebase-hiroba.js` を作り直してください。
